- 2026-07-27: Separate handling for the two Delta-ML use cases (task G). Two preset configurations under `presets/`, loadable through the existing `-import_config` so no new abstraction sits on top of the PARAMs and every value stays visible: `deltaml_conformer.json` (al_mode train, lambda 1e-6, judged on rank correlation and distance to the reference minimum) and `deltaml_trajectory.json` (al_mode learn with on-the-fly sampling at 500 K, judged on gradient RMSE and NVE drift). New CLI test `cli_deltaml_02_trajectory_workflow` covers the second case end to end and generates its own data — short dynamics, fit to the frames, then constant-energy dynamics on the corrected surface — asserting that the held-out gradient error improves and that the run stays finite and thermally sane; no golden numbers, since a 9-atom fixture carries no information about accuracy. Building it surfaced a useful calibration point: the same procedure at 500 K with 42 frames made the forces WORSE (0.088 against 0.051), while 300 K with 302 frames improves them 2.6x (0.015 against 0.040) — sampling temperature and frame count are not incidental to whether a trajectory model helps at all. Suite now 297 tests.

- 2026-07-27: Trisaccharide re-measured after the gradient fixes, and the earlier "train on optimised structures" recommendation is retracted. 66 atoms, GFN-FF to GFN2, M=2000, lambda=1e-6, three training sets: 302 raw 400 K dynamics frames (energy MAE 15.86 vs base 27.42, gradient RMSE 2.56e-2 vs 4.62e-2), 150 GFN-FF-optimised structures (10.37 vs 12.01, 1.08e-2 vs 2.58e-2), 60 GFN2-optimised structures (12.08 vs 64.76, 1.75e-2 vs 5.80e-2). The old claim was 4.8x for optimised against 1.3x for raw frames on the energies; with correct gradients it is 1.16x against 1.73x, i.e. the ordering reverses and the effect is small — the claim does not survive and has been removed from the documentation. **The substantive finding is worse**: all three models move the optimised minimum FURTHER from the GFN2 minimum than bare GFN-FF does (0.894 / 0.793 / 1.012 A against 0.546 A, means over nine structures), and the training set with the largest energy gain gives the worst geometry. A hypothesis that this was a train-where-you-use-it effect is therefore refuted — training directly on GFN2 minima is the worst case. The explanation is that a lower RMS force error does not constrain *where* the gradient vanishes; a floppy sugar with shallow minima amplifies that, while the stiffer 90-atom conformer molecule improved 7-25 % on the same metric. Consequence for the design: conformer work and trajectory work need separate parameter sets and separate acceptance metrics (rank correlation and distance-to-minimum versus gradient RMSE and NVE drift), and the geometric gain must not be assumed to transfer between systems.

- 2026-07-27: Delta-ML re-measured on the corrected surface (task F), default lambda 1e-4 -> 1e-6. With the anchor narrowed and the gradient units fixed, the picture is far more modest than the invalidated figures suggested but internally consistent. 353 conformers / 90 atoms / M=2000, held-out, against base GFN-FF (energy MAE 0.824 kcal/mol, gradient RMSE 9.53e-3 Eh/A, Spearman 0.387, mean distance to the GFN2 minimum 0.635 A over ten optimised conformers, NVE drift 1.56 kcal/mol/ps): lambda=1e-8 gives 0.738 / 1.95e-3 / 0.490 / 0.587 / 1.59; **1e-6** 0.714 / 2.06e-3 / 0.517 / 0.567 / **1.11**; 1e-4 0.709 / 3.83e-3 / 0.350; 1e-2 0.790 / 8.09e-3 / 0.303 / **0.474**. So: gradients improve 4-5x, geometries 7-25 %, relative conformer energies about 13 %, and ranking only at the weaker regularisations — **the gain is in the forces, not the energies**. No single optimum: 1e-6 wins ranking and energy conservation, 1e-2 geometry. Two corrections to earlier claims: the supposed stability-versus-accuracy trade-off in lambda was the gradient unit defect, not physics — every lambda tested now conserves energy at least as well as the base method; and the single-structure geometry metric reported before is useless, individual conformers scatter between 0.34 and 0.68 A with no trend, so the geometry column is now a ten-conformer mean.

- 2026-07-26: On-the-fly active learning (`-al_onthefly`, `-al_onthefly_threshold`), and a defect that made the whole sampling loop run on the wrong method. Each sampling run now carries the extrapolation threshold as an abort condition, so it ends at the first structure outside the trained region and that structure becomes the candidate — the trajectory nominates its own labels instead of a fixed-length batch being filtered afterwards. Verified on a 9-atom system: at threshold 0.5 a cycle collected 4 frames instead of 44, three of them threshold trips. **The defect**: `sampleStructures` wrote its settings as bare top-level keys, but SimpleMD reads through `ConfigManager("simplemd", ...)`, which resolves the module sub-document; `method` therefore fell back to the module default **"uff"**, so every active-learning cycle so far sampled on UFF rather than on GFN-FF or the corrected surface. From the command line the same flags work only because the registry routes them into `controller["simplemd"]` automatically. Settings are now written into the module sub-document as well as flat. Two smaller points found on the way: recording is gated on `uncertainty_warn` while aborting is gated on `uncertainty_abort`, so an abort threshold below the warn threshold aborts without ever recording (on-the-fly mode sets warn to 0.9*abort to avoid it); and molecular dynamics started without a fixed seed gives different trajectories per run, which made the first trigger tests look non-deterministic.

- 2026-07-26: **Two defects that corrupted every Delta-ML force.** Found by finite-differencing the assembled surface rather than the model in isolation — the existing unit test only checked the model against synthetic labels built in its own units, so it could not see either. (1) **The topology anchor froze far more than the bond graph.** `setMolecule(anchor)` then `updateGeometry(actual)` generated the force-field parameters at the anchor geometry while the topology was rebuilt at the real one, and which parts were refreshed depended on how far the structure had travelled — so the potential was not even a smooth function of the coordinates. Measured: analytic gradient vs finite differences 4.7e-3 Eh/Angstrom, against 3.5e-5 for the same method set up normally. Fixed by pinning only the bond graph: the graph is captured once from the anchor (`GFNFF::getCachedBondList`, now public) and handed to every later structure through `Mol::m_bonds`, which GFN-FF already honours as an external graph, while coordination numbers, the parameters derived from them and the charges are computed at the structure being evaluated. (2) **Unit mismatch at the integration seam.** `EnergyCalculator::Gradient()` is Eh/Bohr; the descriptor differentiates with respect to Angstrom, so the learned gradient is Eh/Angstrom. It was added to the base gradient unconverted, inflating the learned force by 1/0.5292 = 1.89 — confirmed by decomposing the total gradient, ratio analytic/FD of the ML part = 1.8894 against 1/BOHR = 1.8897. The training labels had the same defect in reverse (stored in Eh/Bohr against an Angstrom Jacobian), so models were fitted on an inconsistent scale. Both boundaries now convert explicitly. After the fixes the total gradient matches finite differences at 3.5e-5, indistinguishable from the bare base method, and the NVE drift at the default lambda=1e-4 is 1.58 kcal/mol/ps against GFN-FF's 1.56 — i.e. the drift reported earlier was this bug, not insufficient regularisation, and the lambda=1e-2 that appeared to cure it was a symptom-level workaround. **Consequence: every previously reported accuracy, geometry and dynamics figure for Delta-ML is invalid.** On the one system re-measured so far the model is markedly weaker than previously claimed — held-out energy MAE 0.709 vs base 0.824 kcal/mol (was reported 0.299 vs 0.647), rank correlation 0.35 vs base 0.39, and the optimised minimum now sits 0.68 A from the GFN2 minimum against GFN-FF's 0.38 A, i.e. **the correction currently makes the geometry worse**. Re-measurement and a re-tuning of the hyperparameters against the corrected surface are outstanding.

- 2026-07-26: Delta-ML prediction runs on the GPU, and the measurement exposed a defect in the topology anchor. Inference keeps centres, weights and scaling device-resident and exchanges only the standardised descriptor in and the feature-space adjoint out (tens of kB), leaving the ~5 MB compact Jacobian blocks on the host where they are contracted -- the arithmetic is only ~22 MFlop, so traffic decides whether the GPU helps. 90 atoms, M=2000, per dynamics step: GFN-FF alone 0.31 (CPU) / 0.68 (CUDA) ms, Delta-ML total 5.74 / 3.16 ms, i.e. the correction alone 5.43 -> 2.48 ms (2.2x); the correction value is identical to all ten printed digits. GFN-FF itself is SLOWER on the GPU at this size, and `-gpu` is one global switch, so the best per-component placement cannot currently be expressed. **Anchor defect**: with the anchor geometry equal to the input, pure GFN-FF and the Delta-ML base agree on CPU and GPU to 2e-8. As soon as the structure moves off the anchor the CPU path departs by 5.6e-4 Eh (0.35 kcal/mol) while the GPU stays within 1.4e-5 of the geometry-consistent value — the GPU refreshes coordination numbers and the lists derived from them, the CPU keeps them pinned at the anchor. The GPU behaviour is the correct one: CN is a smooth function of the coordinates and belongs to the dynamic state, so pinning it makes the energy wrong for the actual geometry AND inconsistent with the gradient, which is precisely the signature of the NVE drift measured earlier (Delta-ML 5.84 vs GFN-FF 1.56 kcal/mol/ps at lambda=1e-8). The anchor must be narrowed to freeze the bond graph only, and the drift remeasured afterwards. Not fixed in this commit.

- 2026-07-26: Delta-ML fitting runs on the GPU (`-gpu cuda`), plus citations. The fit is dominated by a single symmetric rank-k update per structure (M^2*3N = 2.2 GFlop at M=2000/N=90, against ~0.16 GFlop for building the design block), so that one cuBLAS DSYRK plus the matching DGEMV is what moved to the device via a new `curcuma_cuda_ml_accum_*` entry point in the existing dlopen'd plugin — the main binary stays CUDA-free. The row-major design block needs no repacking: read with leading dimension M it is already the column-major transpose cuBLAS wants, so the two storage conventions cancel. Measured on 353 conformers / 90 atoms / RTX 5080: M=2000 26.2 -> 16.6 s, M=4000 78.6 -> 33.9 s, M=8000 246.9 -> 86.6 s (1.6x / 2.3x / 2.9x, rising with M as the rank-k share grows; ceiling set by the descriptor, Jacobian and design-block construction still on the host). Held-out errors identical to every printed digit at all three sizes. Also added `gpu_plugin::resolveEntryPoint` so consumers other than the method factory reuse the same dlopen cache. Citation database gained `deltaml` (Ramakrishnan et al. 2015), `acsf` (Behler & Parrinello 2007; Behler 2011) and `gap_sparse` (Bartok & Csanyi 2015), cited hierarchically from both the method and the fitting capability. Inference is still CPU-only.

- 2026-07-26: Delta-ML validated against molecular dynamics and geometry, three defects fixed. (a) **lambda had no effect at all**: with W = diag(1/sigma^2) the data block Phi^T W Phi exceeds K_MM by ~1e10, so every value from 1e-8 to 1e2 produced a bit-identical model and only ~1e12 did anything; uniform rescaling of W is equally inert because it cancels out of the solution, leaving only the energy-to-force ratio. lambda is now referred to the data scale (`lambda * mean(diag(A)) * K_MM`), which makes it behave like its name, default 1e-4. (b) **MethodFactory lower-cased the whole method string**, including the file path in the `deltaml:<path>` shorthand — any model whose name contained an upper-case letter failed to load on a case-sensitive filesystem. (c) the flat `-lambda` flag does not route to the activelearn module; documented, dotted form works. Measurements (90-atom conformer molecule, GFN-FF to GFN2, each NVE run started from a structure optimised on its own surface — without that pre-optimisation the test measures starting-point mismatch instead of conservation, and the same triose model drifted 29.9 kcal/mol/ps heating 300 K to 544 K): NVE drift GFN2 0.10, GFN-FF 1.56, Delta-ML 5.84 / 2.71 / 1.58 kcal/mol/ps at lambda 1e-8 / 1e-4 / 1e-2 — **at 1e-2 the learned surface conserves energy as well as the base method**, on the trisaccharide better (0.96 vs 1.22). Optimised minimum vs the GFN2 minimum: GFN-FF 0.377 A, Delta-ML(1e-4) **0.119 A**, i.e. 3.2x closer — but system dependent, the trisaccharide gave 0.288 vs 0.273 A (5 %) while its energies improved 4.8x. **Biggest single lever is the training set, not any hyperparameter**: on the trisaccharide, 302 raw 400 K dynamics frames (Delta spanning 371 kcal/mol) gave a 1.3x energy gain and made the optimised geometry WORSE than bare GFN-FF (0.405 vs 0.288 A), while 150 GFN-FF-optimised structures (Delta spanning 91 kcal/mol) gave 4.8x. Train on optimised structures for pre-optimisation work.

- 2026-07-26: Delta-ML active learning (`-activelearn -al_mode learn`). Each cycle samples with molecular dynamics on the currently corrected surface, selects candidates by greedy farthest-point in descriptor space among those above the uncertainty threshold (pure uncertainty maximisation piles every pick onto one pathological region), labels them with base and reference, refits and writes a learning curve. Two defects found while bringing it up: (a) SimpleMD redirects its whole output into `<basename>.snapshots` and then builds paths as outputDir + "/" + basename, so a basename containing a directory separator points into a directory nobody creates and the trajectory is dropped with no error — the run tag is now a plain name and the scratch is collected and removed afterwards; (b) restoring the global logger verbosity after `StartAndWait` but before deleting the MDThreads gets clobbered, because each thread owns a SimpleMD whose CurcumaMethod destructor restores the level it captured at construction, i.e. the silenced one — restore now happens after the threads are gone. Also recalibrated the convergence threshold: the indicator `1 - max_m k` saturates fast with a Gaussian kernel (d = 1.18 sigma reads 0.5, d = 2.1 sigma reads 0.9), so the original default of 0.05 demanded d < 0.32 sigma and could never fire; default is now 0.5 and the log additionally prints the nearest-centre distance in units of sigma, which stays informative after the bounded indicator flattens. **Status: the loop runs and grows its dataset, its benefit is NOT demonstrated** — the 9-atom trial left only a handful of held-out structures, so its error estimates are noise. The offline path is the one with measured results. Known structural weakness, documented not fixed: sampling happens on the surface being learned, so cycle 0 only visits what the base method considers relevant and the model can confirm itself; uncertainty-triggered on-the-fly labelling inside the dynamics would be the robust alternative.

- 2026-07-26: Delta-ML added (`-activelearn` to fit, `-method deltaml:<model.json>` to use). Learns `E_ref - E_base` so conformer search and pre-optimisation run at base-method cost while ranking at reference level. ACSF descriptor (Behler G2/G4, element-resolved, analytic derivatives in compact per-atom Jacobian blocks so memory stays linear rather than quadratic) plus sparse kernel ridge in the subset-of-regressors form GAP uses: `Delta(A) = sum_Z n_Z c_Z + sum_i sum_m beta_m k(x_i, z_m)` over M farthest-point-sampled centres, element-blocked kernel, element-count baseline absorbing the energy-zero offset with zero gradient. Energies and gradients trained jointly — one reference point gives 1 energy but 3N gradient components, which is what makes a few hundred points enough. M bounds prediction cost independently of dataset size; that is not an optimisation but a requirement, since a dense kernel over all 25380 training environments would be slower than the reference it replaces. Measured on 353 conformers of a 90-atom C/H/N molecule, GFN-FF to GFN2, 282/71 split: relative conformer energy MAE 0.647 -> 0.167 kcal/mol, gradient RMSE 5.04e-3 -> 0.90e-3 Eh/A, Spearman 0.41 -> 0.89 at M=4000, monotone in M; steady-state MD cost 0.91 (GFN-FF) / 4.83 (Delta-ML M=2000) / 80.1 (GFN2) ms per force evaluation, i.e. 16.6x faster than the reference. Verified: descriptor Jacobian shows textbook h^2 convergence to the roundoff floor with translation invariance 2e-16 and rotation 1e-15 (exact analytic identities, sharper than the FD comparison itself), model gradient matches FD to 1.2e-11 Eh/A, JSON round-trip bit-exact. Limits: fixed topology only (GFN-FF freezes its bond list at setup, so reactions are out of scope), one molecule per model, and the reference MUST carry the same dispersion treatment as the base — with matching D4 the dispersion residual in Delta decays as r^-12 and sits inside the cutoff, without it the full r^-6 term lands in a local descriptor that cannot represent it. Active learning (`-al_mode learn`) not implemented yet. See docs/DELTA_ML.md.

- 2026-07-26: Fixed a silent parameter-registry dropout. The param parser declared a PARAM malformed as soon as any ')' appeared in the accumulated text, which a multi-line help string containing parentheses satisfies on its very first line; it then cleared its buffer and lost that parameter and every later one in the same block. gfnff.h carried a comment working around it by keeping PARAMs on single lines. The parser now resyncs on the next PARAM instead. Registry grows 577 -> 613 definitions; 22 of the recovered ones are pre-existing (the other 14 are the new activelearn/deltaml modules): the ENTIRE `eeq_solver` module (18 params) had been dropped, plus `gfnff.eeq_refactor_eps_bohr`, `gfnff.eeq_refactor_force_every`, `gfnff.solvent` and `gfnff.solvent_model`. Since ConfigManager seeds itself from the registry, dropped params fell through to the hard-coded fallbacks in eeq_solver.cpp. Sixteen of the eighteen registry defaults match those fallbacks exactly, so nothing moves; **two do not and are now in effect**: `max_pcg_iterations` 100 -> 200 and `pcg_large_system_iterations` 100 -> 5000, i.e. the declared PARAM intent replaces stale fallbacks. Both are iteration ceilings, so the PCG may now converge where it previously bailed out early; all 23 gfnff and both eeq ctests pass unchanged. Note `gfnff.solvent` was never actually reaching the code either, contrary to the comment in gfnff.h claiming its registration fixed that; the default is "none" so gas-phase runs are unaffected, but `-gfnff.solvent water` behaves differently now (namely, as documented).

- 2026-07-26: Delta-ML normal equations get a relative conditioning ridge (`-jitter_relative`, default 1e-8). Accumulating `Phi^T W Phi + lambda K_MM` avoids materialising a design matrix with 3N rows per structure, but squares the condition number, and K_MM is near-singular once many centres crowd together. Without the ridge, LDLT reported success and returned an oscillating solution: at M=4000 the training MAE stayed at 0.145 kcal/mol while the held-out MAE blew up to 0.554, i.e. accuracy got WORSE as centres were added, which a regularised fit cannot do. With the ridge, 0.099 / 0.167 and the M sweep is monotone.
