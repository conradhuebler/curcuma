- **GeometryTools: angle, dihedral, radius of gyration; BestFitRotation guard fixed (Sep 2026)**: `GeometryTools::Angle` (degrees, clamped acos so a straight or folded arrangement does not return NaN), `GeometryTools::Dihedral` (signed degrees, IUPAC) and `GeometryTools::GyrationRadius(const Geometry&)` (unweighted shape measure; the mass-weighted, PBC-aware and per-fragment variants stay on `Molecule::GyrationRadius`). - **Periodic container wall + termination reason (Sep 2026)**: `wall_potential = pbc` is a third wall behaviour next to harmonic and logfermi. It exerts NO force: `SimpleMD::wrapIntoContainer()` moves a whole fragment that left the container back in on the opposite side (per axis for a box, to the antipodal point for a sphere), so unlike the two potentials it does not do work on an escaping molecule and does not heat the system. Whole fragments are translated by one common vector, never single atoms, because tearing a molecule across the boundary would stretch its bonds to container size and the reactive scan would then break the bond. **Deliberately incomplete**: the energy has no minimum-image convention, so a wrapped fragment does not continue its interactions across the boundary and its destination can be occupied (measured on 2 N2 + 6 H2 at 3000 K in a 4.5 A sphere: a wrap landed 0.024 A from another atom and the run turned NaN one step later). Until the non-bonded terms are periodic, a wrap into occupied space is refused and the fragment is reflected elastically instead, which conserves kinetic energy exactly. Contained and free of heating, but not periodic — the real fix is scoped in `docs/WP-PERIODIC-NONBONDED.md`. Measured confinement over 20 ps in a 4.5 A sphere, largest final distance from the origin: harmonic 11.00 A, logfermi 8.76 A, pbc 4.98 A. Also added: `SimpleMD::stopReason()`/`stopReasonText()`, because every abort message is gated behind verbosity 1 and the normal end-of-time exit prints nothing at all, so a driver running the loop itself (the qurcuma GUI) could not tell a finished run from one that fell apart. 🤖 machine-tested.

- **GFN-FF react mode: public topology/event API + scan bookkeeping fixes (Sep 2026)**: the react bond list, its bond orders and its change events are now readable from a driver — `reactiveBonds()`, `reactiveBondOrders()`, `reactiveRebuildCount()`, `consumeReactEvents()` (`ReactEvent{call, formed, broken, de_jump_eh}`), `topologyMode()`, plus `getGFNFF()` on the CUDA/ROCm wrappers — so a GUI can draw and log exactly what the force field integrates instead of re-detecting bonds geometrically. `dE_jump` is now measured at every rebuild (not only at verbosity >= 1) and its definition is stated: E(new topology, its EEQ charges) - E(old topology, its charges) at the same geometry. Bond orders are `1 + round(pi)` plus the second, degenerate pi system for sp-sp bonds, because the FT-Hueckel solver models ONE pi system and reports ~1.0 for a double bond AND a triple bond alike (measured: ethylene C=C 1.000, N2 0.999, CO 0.994, acetylene C#C 1.000, acetylene C-H 0.000); btyp cannot serve, it marks every bond at an sp atom. Seven bookkeeping fixes: the react set owns the bond list even when EMPTY (previously an all-broken system silently fell back to geometric detection with a different criterion); the refractory period blocks N instead of N-1 scans; exchange resolution decrements sigma counts and no longer breaks a bond formed in the same scan; react state is cleared on re-initialisation; a throwing rebuild rolls back instead of leaving engines and bond list disagreeing; a NaN geometry aborts the scan with a warning instead of silently doing nothing; the slack-radius filter is gated on `react_valence_cap` as its help text promises; the displacement trigger uses a per-atom norm rather than the largest single component. `rattle` + react is now refused at initialisation (constraints are frozen at init and cannot follow a changing topology). Dead `cloneCachedParameterSet()` removed; the GPU parameter-set leak comment corrected from "one-time" to per rebuild. New tests: `gfnff_react_filters` (scan bookkeeping in isolation) and `cli_simplemd_15_gfnff_react_water_noevent` (gfnff-optimised cyclic water hexamer, 6 H-bonds at 1.90 A, 300 K: zero events, bit-identical to auto — the case the 1.60 A O-H formation radius comes closest to). 5/5 react ctests, 17/17 `gfnff_val_*` Fortran-parity references unchanged. Also corrected: the `hybridization` comment in `gfnff.h` had 0 and 3 swapped (the producing function documents 0 = none/octahedral, 3 = sp3). 🤖 machine-tested.

- **gfnff is now the default method for every capability (Sep 9, 2026)**: `-sp`, `-opt`, `-md`, `-hessian`, `-confsearch` and `-casino` previously fell back to `uff` in six places (casino.h/cpp, simplemd.h, hessian.cpp x2, curcumaopt.cpp x4, scnp_parser.cpp) while curcumaopt.h and confsearch.h had already moved to gfnff - so the registry default and the C++ fallback disagreed.
