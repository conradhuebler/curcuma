# AI-Generated Changes Log

This file tracks significant improvements, refactorings, and new features generated by AI assistants (primarily Claude).

Format: One line per change, newest first.

- **ANCOpt honours held atoms (Sep 2026)**: `OptimizerDriver::setConstraints` zeroed the Cartesian gradient of held atoms, but ANCOpt moves along approximate normal coordinates built from the model Hessian, so every step still mixed held and free atoms (heavy atoms drifted 0.04 A in a "hydrogens only" relaxation). Now the frozen Cartesian DOFs are projected out of the model Hessian before the eigen-decomposition (`projectFrozenAtoms`, replacing the translation/rotation projection, which no longer applies once atoms are pinned), the rows of the frozen DOFs in the coordinate basis are zeroed, and the number of internal coordinates is 3*free minus 3 (none or one held), 1 (two held: rotation about their axis) or 0 (three or more). Measured on ethanol with C-H/O-H shortened to 0.95/0.85 A (X-ray riding model): heavy atoms 0.00000 A with ancopt, lbfgs and rfo; C-H 1.092 A, O-H 0.985 A afterwards. 🤖 machine-tested.
- **CIF: complete molecules, space group, Z, formula (Sep 2026)**: `CifBuildOptions::complete_molecules` reassembles molecules cut by the cell faces (breadth-first over bonds that may cross a face, bond = 1.15 x sum of covalent radii, each molecule then shifted so its centroid lies in [0,1)), like Mercury's "complete molecules". `CifData` gained `space_group` (H-M), `space_group_number`, `formula_units_z`, `formula_sum` and `formula_moiety` (also as a `;` text field), so a caller can check that the asymmetric unit holds Z/ops formula units. `test_cif` covers both (a C-O pair across the x face: 8.8 A apart wrapped, 1.2 A completed, centre in the cell; the moiety read from a text field). 🤖 machine-tested.
- **CIF: displacement parameters (Sep 2026)**: `CifSite` carries U_aniso (from `_atom_site_aniso_U_ij`, or B_ij / 8 pi^2) and U_iso (`_atom_site_U_iso_or_equiv` / `B_iso`); `BuildCif(data, options, &displacements)` returns one Cartesian tensor per atom, U_cart = M N U N M^T with N = diag(a*, b*, c*), turned for every symmetry image (U* -> R U* R^T). `test_cif`: a 4-fold axis swaps U11/U22; in a monoclinic cell trace(U_cart)/3 equals the textbook U_eq including the cos(beta) term. 🤖 machine-tested.
- **CIF reader: disorder groups, asymmetric unit, per-site periodic deduplication, one data block (Sep 2026)**: `ReadCifData()` reads occupancy, disorder assembly and group (SHELX PART) per site and summarises the groups; `BuildCif()` builds the asymmetric unit (coordinates as written, unwrapped) or the unit cell, with every disorder alternative or one group. Two defects fixed on the way: (1) duplicates were found by comparing each generated atom with EVERY earlier atom of the same element, so a disorder alternative within 0.1 A of its partner was swallowed (a Pbca structure lost 48 of 816 atoms); now only images of the same site are compared, periodically, which also fixes (2) a site at 0.00001 being kept a second time at 0.99999. And several data blocks were read as one structure under the last block's cell; now the first block with atom sites is read, with a note. `ReadCif()` keeps its meaning (unit cell, all alternatives) plus a note when the alternatives overlap. `test_cif` 25/25 (disorder, face, asymmetric unit, data blocks). 🤖 machine-tested.
- **CIF reader locale-independent (Sep 2026)**: numbers were parsed with `std::stod`, which follows the process locale — inside a Qt GUI that adopted de_DE, "0.5957" read as 0 and a 5.6402 A cell as 5 (every coordinate truncated, Cl on top of Na in NaCl). Now `std::from_chars` (a stream fixed to the classic locale where libc++ lacks floating-point `from_chars`, i.e. older Apple Clang; both paths pass `test_cif`), also in the symmetry-operation parser, where a malformed token (".", "/2") used to throw uncaught and is now counted as an unreadable operation. `test_cif` gained a de_DE case (skipped where the locale is not installed). 🤖 machine-tested.
- **`Molecule::addPair` no longer O(N^3) (Sep 2026)**: the coincident-atom check re-tested every pair on every call, so building a molecule atom by atom cost O(N^3) — measured 16.4 s for 3400 atoms, which made qurcuma's `select_atoms` time out on a filled water box. It now compares only the new atom against the existing ones (14 ms). The one caller that reads the return value (`rmsd.cpp`, reorder candidate test) asks exactly that question. `molecule_comprehensive` and `cli_rmsd_*` pass; `cli_confscan_02/03/05` fail identically with the old code (missing "All 44 input structures were read" log line). 🤖 machine-tested.
- **GeometryTools: angle, dihedral, radius of gyration; BestFitRotation guard fixed (Sep 2026)**: `GeometryTools::Angle` (degrees, clamped acos so a straight or folded arrangement does not return NaN), `GeometryTools::Dihedral` (signed degrees, IUPAC) and `GeometryTools::GyrationRadius(const Geometry&)` (unweighted shape measure; the mass-weighted, PBC-aware and per-fragment variants stay on `Molecule::GyrationRadius`). They joined the existing `Distance` because the qurcuma GUI needed them and a second implementation there would drift from curcuma. **Bug fixed in `RMSDFunctions::BestFitRotation`**: the degeneracy guard tested `det(Cov) < 1e-10`, but a vanishing determinant means the covariance is RANK DEFICIENT, not degenerate — every PLANAR structure (benzene, any three atoms, any flat fragment) has `det(Cov) = 0` while its Kabsch rotation is perfectly well defined and the SVD recovers it. Bailing out to the identity left planar structures unaligned and reported their RMSD against the unrotated target; measured on a square turned by 90 degrees, RMSD sqrt(2) instead of 0. The guard now tests `Cov.norm()`, which is what "numerically zero covariance" actually means. New ctest `geometry_tools` pins all of it including the planar rotation. 23/23 gfnff_val + react + geometry ctests pass. Separately recorded in `test_cases/cli/KNOWN_BUGS.md`: `cli_simplemd_13_rmsd_mtd_legacy_ab` passes only on a repeat run because the legacy MTD path looks for `input.mtd.xyz` in the CWD while writing it into the BMT directory — pre-existing, verified against the unmodified tree. 🤖 machine-tested.

- **Periodic container wall + termination reason (Sep 2026)**: `wall_potential = pbc` is a third wall behaviour next to harmonic and logfermi. It exerts NO force: `SimpleMD::wrapIntoContainer()` moves a whole fragment that left the container back in on the opposite side (per axis for a box, to the antipodal point for a sphere), so unlike the two potentials it does not do work on an escaping molecule and does not heat the system. Whole fragments are translated by one common vector, never single atoms, because tearing a molecule across the boundary would stretch its bonds to container size and the reactive scan would then break the bond. **Deliberately incomplete**: the energy has no minimum-image convention, so a wrapped fragment does not continue its interactions across the boundary and its destination can be occupied (measured on 2 N2 + 6 H2 at 3000 K in a 4.5 A sphere: a wrap landed 0.024 A from another atom and the run turned NaN one step later). Until the non-bonded terms are periodic, a wrap into occupied space is refused and the fragment is reflected elastically instead, which conserves kinetic energy exactly. Contained and free of heating, but not periodic — the real fix is scoped in `docs/WP-PERIODIC-NONBONDED.md`. Measured confinement over 20 ps in a 4.5 A sphere, largest final distance from the origin: harmonic 11.00 A, logfermi 8.76 A, pbc 4.98 A. Also added: `SimpleMD::stopReason()`/`stopReasonText()`, because every abort message is gated behind verbosity 1 and the normal end-of-time exit prints nothing at all, so a driver running the loop itself (the qurcuma GUI) could not tell a finished run from one that fell apart. 🤖 machine-tested.

- **GFN-FF react mode: public topology/event API + scan bookkeeping fixes (Sep 2026)**: the react bond list, its bond orders and its change events are now readable from a driver — `reactiveBonds()`, `reactiveBondOrders()`, `reactiveRebuildCount()`, `consumeReactEvents()` (`ReactEvent{call, formed, broken, de_jump_eh}`), `topologyMode()`, plus `getGFNFF()` on the CUDA/ROCm wrappers — so a GUI can draw and log exactly what the force field integrates instead of re-detecting bonds geometrically. `dE_jump` is now measured at every rebuild (not only at verbosity >= 1) and its definition is stated: E(new topology, its EEQ charges) - E(old topology, its charges) at the same geometry. Bond orders are `1 + round(pi)` plus the second, degenerate pi system for sp-sp bonds, because the FT-Hueckel solver models ONE pi system and reports ~1.0 for a double bond AND a triple bond alike (measured: ethylene C=C 1.000, N2 0.999, CO 0.994, acetylene C#C 1.000, acetylene C-H 0.000); btyp cannot serve, it marks every bond at an sp atom. Seven bookkeeping fixes: the react set owns the bond list even when EMPTY (previously an all-broken system silently fell back to geometric detection with a different criterion); the refractory period blocks N instead of N-1 scans; exchange resolution decrements sigma counts and no longer breaks a bond formed in the same scan; react state is cleared on re-initialisation; a throwing rebuild rolls back instead of leaving engines and bond list disagreeing; a NaN geometry aborts the scan with a warning instead of silently doing nothing; the slack-radius filter is gated on `react_valence_cap` as its help text promises; the displacement trigger uses a per-atom norm rather than the largest single component. `rattle` + react is now refused at initialisation (constraints are frozen at init and cannot follow a changing topology). Dead `cloneCachedParameterSet()` removed; the GPU parameter-set leak comment corrected from "one-time" to per rebuild. New tests: `gfnff_react_filters` (scan bookkeeping in isolation) and `cli_simplemd_15_gfnff_react_water_noevent` (gfnff-optimised cyclic water hexamer, 6 H-bonds at 1.90 A, 300 K: zero events, bit-identical to auto — the case the 1.60 A O-H formation radius comes closest to). 5/5 react ctests, 17/17 `gfnff_val_*` Fortran-parity references unchanged. Also corrected: the `hybridization` comment in `gfnff.h` had 0 and 3 swapped (the producing function documents 0 = none/octahedral, 3 = sp3). 🤖 machine-tested.

- **gfnff is now the default method for every capability (Sep 9, 2026)**: `-sp`, `-opt`, `-md`, `-hessian`, `-confsearch` and `-casino` previously fell back to `uff` in six places (casino.h/cpp, simplemd.h, hessian.cpp x2, curcumaopt.cpp x4, scnp_parser.cpp) while curcumaopt.h and confsearch.h had already moved to gfnff - so the registry default and the C++ fallback disagreed. All capability-level defaults are gfnff now, and the method help texts state the intent: **gfnff is the fast general-purpose choice, gfn2 the accurate one** (~100x slower, real electronic structure). Documented in the CLI help (`-opt` usage block), the method PARAM descriptions, README and CLAUDE.md. Deliberately NOT changed: `ForceFieldGenerator`'s own `method` parameter stays `uff` - it selects which FORCE FIELD the FF engine builds (uff | uff-d3 | qmdff | cg), GFN-FF does not go through that class, and its `ff_type = 4` branch there is dead code (only `== 1` and `== 2` are consumed downstream) since the legacy ForceField GFN-FF path was removed in the Sep 2026 cleanup; switching it would silently produce a force field with no bonded terms.
